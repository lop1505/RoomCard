# RoomCard v1.4.0 — History details, Room Modes & adaptive rooms

More useful room controls, richer sensor history, and headers that adapt to your room. New features are opt-in; existing YAML configurations require no migration.

## 📈 Explore sensor history

Enable `sparkline_detail: true` on a sensor control with `show_sparkline: true` to open a dedicated history dialog. Switch between **6h, 24h, and 7d**, see the current Home Assistant-formatted value, and compare **Min / Max / Average**. Sparkline clicks remain separate from the control's configured actions.

![Sparkline detail dialog with time ranges and statistics](https://raw.githubusercontent.com/lop1505/RoomCard/v1.4.0/docs/images/releases/v1.4.0/sparkline-detail-24h-dark.png)

*This real battery sensor remained at 100%, so the captured history is intentionally flat.*

## 🎬 Room Modes, always within reach

Add `room_modes` for scenes and scripts, customize their names, icons and colors, and optionally highlight active modes with `active_when` conditions. The mode strip stays visible when room controls are collapsed and scrolls horizontally on narrow screens.

## 🖼️ Adaptive header images

Use ordered `adaptive_images` rules to select a background by entity state, numeric value, time, user, screen size, or combined conditions. Each rule can have its own image and focal point. The first matching rule wins; otherwise your existing default image is used.

This release also fixes header-image initialization for cards configured before they are inserted into the dashboard. Existing preset, custom URL, and uploaded images work without any adaptive rules.

![Adaptive image rule with image selection, focal position, and conditions](https://raw.githubusercontent.com/lop1505/RoomCard/v1.4.0/docs/images/releases/v1.4.0/adaptive-images-editor-dark.png)

## 📊 Room status at a glance

Configure `status_groups` to count active lights, open windows, or playing media, or show numeric summaries such as combined power. Optional detail dialogs show contributing entities. Compatible power units are normalized; incompatible numeric units are rejected.

## 🌍 Localization and reliability

- English, German, and French include all 318 translation keys, with automated completeness and placeholder checks.
- Missing French visibility, sub-chip, and climate-button labels are filled in; the German template-state label is corrected.
- Regression coverage includes default images without rules, reconnecting cards, returning to the default, removing the final rule, and rejecting stale image loads.

## ✅ Validation

- **68 automated tests**, syntax checks, distribution/version checks, and a deterministic rebuild.
- Manual Home Assistant testing was reported successful for default/adaptive images and fallback, sparkline details, Room Modes, room status, saving/reloading, mobile, and light/dark themes.
- The final localization changes are covered by automated tests; a separate visual English/French pass was not performed.

## ⬆️ Updating

Update through HACS, then fully reload the dashboard. If you used a commit-pinned CDN resource for testing, switch the existing RoomCard resource back to the HACS-managed resource after updating. Do not keep both builds registered as separate resources.

For manual installation, copy `dist/room-card.js` together with `dist/rooms/` from the source archive, keeping the script and its adjacent `rooms/` directory together. The `rooms/` directory contains the bundled header images.

See the [README](https://github.com/lop1505/RoomCard/blob/v1.4.0/README.md) for configuration examples and the [full changelog](https://github.com/lop1505/RoomCard/blob/v1.4.0/CHANGELOG.md) for all changes.
