# RoomCard v1.5.1 — Accurate room status and easier setup

This patch fixes numeric room-status summaries, adds a readable value-source picker
for cover positions and other numeric attributes, and updates the editor for Home
Assistant's frontend component changes. Existing YAML remains supported.

## 📊 Accurate numeric summaries

Unitless template sensors now work with a configured output unit: a state of `65`
with unit `%` displays **65 %**. Switching from Count to Numeric sum no longer
leaves a hidden active-state filter that discards numeric values.

When no valid numeric values are available, the chip shows **—** with an explanation
instead of a misleading zero. Actual zero values still respect **Hide when zero**,
and compatible power-unit conversion remains supported. Fixes [#159](https://github.com/lop1505/RoomCard/issues/159).

## 🎛️ Cover positions without extra templates

In **Room status → Numeric sum → Value source**, choose **State**, **Position (%)**,
**Tilt position (%)**, or another shared numeric attribute. Attribute names use
Home Assistant's translated labels when available.

Cover groups suggest Position and fill the output unit with `%` when switching to
Numeric sum or adding covers to a new empty numeric group. Existing configurations
and temporarily unavailable custom attributes are retained when opening the editor.

Positions follow Home Assistant: **0 % means closed, 100 % means open**. A position
of 94 % therefore corresponds to 6 % closed on the shutter control. Existing
numeric template sensors continue to work; YAML can also specify
`attribute: current_position` directly.

## 🪟 Contact icons and Home Assistant compatibility

* Window, door and garage contact chips use the appropriate open/closed icons and
  honor custom entity icons. Fixes [#154](https://github.com/lop1505/RoomCard/issues/154).
* Translated static and dynamic editor switch labels use the control's own label
  slot for HA 2026.11 compatibility. Fixes [#155](https://github.com/lop1505/RoomCard/issues/155).
* Default entity labels follow Home Assistant's native naming and update when
  relevant entity, device, area or floor names change. Explicit RoomCard labels
  remain intact, with safe fallbacks for older HA versions. Fixes [#156](https://github.com/lop1505/RoomCard/issues/156).

## ✅ Validation and updating

The release passes **138 automated tests**, syntax checks, deterministic bundle
comparison and release-metadata checks. The maintainer confirmed the tested changes
work on **Home Assistant 2026.10.4**. Live HA 2026.11 Marketplace installation,
migration and update checks remain tracked in [#157](https://github.com/lop1505/RoomCard/issues/157).

Update through HACS, then fully reload the dashboard. If testing used a commit-pinned
resource URL, switch that existing resource back to the HACS-managed RoomCard URL.

For manual installation, the attached **room-card-v1.5.1.zip** contains
`room-card.js` and the adjacent `rooms/` image directory. Copy both together. The
source archive also contains the complete `dist/` directory.
