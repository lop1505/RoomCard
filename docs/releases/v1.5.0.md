# RoomCard v1.5.0 — Room details, modular foundations

More room for your controls, without crowding your dashboard. This release adds an optional Room Detail Drawer and completes a staged source-code modularization. Existing YAML requires no migration.

## 🚪 A dedicated space for each room

Open room details using the new header button, or assign `action: room-details` explicitly. Desktop uses a right sidebar; narrow screens use a bottom sheet. Your room image, information, status groups and Room Modes come from the existing card configuration.

![Real Home Assistant room-detail view with header image, climate, light and cover controls](https://raw.githubusercontent.com/lop1505/RoomCard/v1.5.0/docs/images/releases/v1.5.0/room-detail-controls.png)

*User-provided detail crop from the real Home Assistant installation, with mixed English/German labels. It illustrates the content, not the complete desktop sidebar or mobile layout. A mobile screenshot is not included.*

## 🎛️ One configuration, two places

Choose **Card**, **Room details**, or **Both** for each control in the visual editor. Controls share state and configuration but use independent DOM nodes and listeners.

```yaml
detail_drawer:
  enabled: true
  title: Living room
controls:
  - entity: light.ceiling
    display_in: both
  - entity: cover.window
    display_in: drawer
```

The default placement remains `card`. Disabling the drawer returns its controls to the card, respecting existing hide and visibility settings. Existing header actions and collapse behavior are not replaced.

## ♿ Coordinated dialogs and lifecycle

History, room-status and Home Assistant more-info dialogs work above room details with coordinated focus, Escape handling and focus restoration. Closing, navigation, removal and disabling clean up the drawer. History requests retain shared caching and deduplication; there is no second polling timer.

The editor adds enable/title/preview settings, control placement and duplication, with English, German and French translations and existing live-preview/save behavior.

## 🧩 Modular inside, simple to install

Helpers, translations, runtime, compatibility handling and editor now have explicit module boundaries. The pinned esbuild 0.28.2 build still delivers one readable `dist/room-card.js`, with no runtime imports or framework change, and adjacent `dist/rooms/` images.

## ✅ Reliability and validation

- 119 automated tests, JavaScript syntax checks, deterministic fresh-build comparison, registration checks and relative-image/HACS layout checks.
- Fix conditional sparkline startup before Home Assistant supplies `hass`.
- Exclude drawer-only controls from the dashboard card-size estimate.
- Treat malformed optional status groups as empty instead of leaving a broken modal.
- The staged manual Home Assistant checks were reported successful by the maintainer. Final live-browser inspection confirmed the integrated drawer, three configured controls and return from room-status details.
- The final two review fixes are covered by regression tests; no separate physical-device retest of those fixes was performed.

## ⬆️ Updating

Update through HACS, then fully reload the dashboard. If you used a commit-pinned CDN resource for testing, replace that resource with the HACS-managed RoomCard resource after updating. Do not load the test build and HACS build as separate resources.

For manual installation, copy `dist/room-card.js` and `dist/rooms/` from the source archive, keeping the script and its adjacent `rooms/` directory together.
