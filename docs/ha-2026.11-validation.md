# Home Assistant 2026.11 compatibility and Marketplace validation

Status as of 2026-11-01. Fixes #154, #155, #156 and #159 are covered by automated
regression checks. Issue #157 remains open for live Marketplace/release testing.

## Evidence collected

* `npm run build` and `npm run check` pass, including 138 automated tests.
  The tests exercise the shipped bundle, its deterministic rebuild, single-module
  registration, relative HACS/CDN/local asset URLs and all 16 bundled room images.
* `hacs.json` names the existing `room-card.js` artifact, `dist/` contains that
  bundle and its `rooms/` assets, and CI already runs HACS validation as `plugin`.
  The documented packaging requirements show no need to change the manifest or
  introduce migration code.
* RoomCard is present in the shared HACS/Marketplace catalog:
  [`hacs/default` plugin list](https://github.com/hacs/default/blob/ba982c4cfec8e6077ea593570545a761fc740556/plugin)
  contains `lop1505/RoomCard`. This verifies catalog inclusion, not the live
  Marketplace installation flow.
* The available Home Assistant instance reports Core **2026.10.4**, Frontend
  **20260930.5** in Safari on macOS. Its About page, card configuration and raw
  entity state were inspected read-only. A direct cover summary reproduced the
  missing numeric source: state `open`, position attribute `94`. This case is now
  covered by regression tests and a readable Value source dropdown, including a
  Position (%) suggestion for cover groups. The
  candidate bundle was not deployed and no upgrade was performed.

## Official compatibility references

* [Frontend component changes](https://contributors.home-assistant.io/blog/2026/10/28/frontend-component-updates-2026.11/):
  switch labels belong in the default slot after removal of the form-field wrapper.
  Both static and dynamic editor paths use that contract; editor DOM revision 10
  refreshes already-open editors. The
  [20260930.5 switch source](https://github.com/home-assistant/frontend/blob/20260930.5/src/components/ha-switch.ts)
  also uses the Web Awesome switch, but live label-click checks remain pending.
* [HA name formatter](https://contributors.home-assistant.io/frontend/reference/hass-object/#formatentityname):
  default entity labels now delegate to `hass.formatEntityName()` when available.
  Explicit control text remains unchanged, including intentional empty strings;
  older HA versions and missing registry data fall back safely.
* [Dashboard packaging](https://contributors.home-assistant.io/marketplace/guides/dashboard/):
  the explicit filename and bundled `dist/` assets fit the existing plugin format.
  README installation guidance now distinguishes Marketplace from older HACS.
* [Marketplace migration and releases](https://contributors.home-assistant.io/marketplace/how-it-works/):
  the shared catalog and manifest remain applicable. Existing HACS resource paths
  are documented as compatible. These published contracts still need the live
  RoomCard checks below.
