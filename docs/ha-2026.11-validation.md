# Home Assistant 2026.11 compatibility and Marketplace validation

Status as of 2026-11-13. Fixes #154, #155, #156 and #159 are covered by automated
regression checks. The #161 image-packaging candidate has automated asset-install
coverage; issue #157 remains open for clean-install, migration and release-update
testing.

The #158 automatic-section implementation is also available locally as an
unreleased candidate. Its stable adapter retains the ordinary RoomCard while
registry membership changes; the section picker, save/reopen flow and actual HA
registry updates still need live acceptance testing. See the
[implementation notes](automatic-room-sections.md) and
[2026-11-13 test checklist](testing/2026-11-13.md). No release was created.

## Evidence collected

* The v1.5.1 `npm run build` and `npm run check` passed 138 automated tests.
  The tests exercise the shipped bundle, its deterministic rebuild, single-module
  registration, relative HACS/CDN/local asset URLs and all 16 bundled room images.
  The initial #161 candidate passed **139 tests**; the combined #158/#161
  candidate now passes **159 tests**, syntax, deterministic rebuild and
  release-metadata checks. All 16 moved JPEGs retain their recorded SHA-256
  checksums. The release workflow's upload step was exercised with a mock GitHub
  CLI: it passes all 17 individual assets to upload for a draft and rejects a
  published release. This dry run did not upload files or publish a release.
* `hacs.json` names the existing `room-card.js` artifact, and CI runs HACS
  validation as `plugin`. The previous packaging assessment missed release-asset
  selection: v1.5.1 attaches `room-card.js` and a supplementary ZIP, but no
  individual JPEGs. Marketplace prefers those release assets and writes the ZIP
  as a file; it does not extract the image directory from it (see the
  [HA 2026.11 release-asset download](https://github.com/home-assistant/core/blob/2026.11.0/homeassistant/components/marketplace/repositories/plugin.py#L249)
  and [file-writing implementation](https://github.com/home-assistant/core/blob/2026.11.0/homeassistant/components/marketplace/repositories/base.py#L1809)). The candidate moves
  all JPEGs directly beside the bundle and adds a draft-release upload workflow.
  A new test installs only that individual asset list into an empty directory and
  resolves all 16 image files under Marketplace/HACS, manual, CDN and proxy URLs.
  No manifest change or dashboard configuration migration is required.
* RoomCard is present in the shared HACS/Marketplace catalog:
  [`hacs/default` plugin list](https://github.com/hacs/default/blob/ba982c4cfec8e6077ea593570545a761fc740556/plugin)
  contains `lop1505/RoomCard`. This verifies catalog inclusion, not the live
  Marketplace installation flow.
* On 2026-11-01 the available Home Assistant instance reported Core **2026.10.4**, Frontend
  **20260930.5** in Safari on macOS. Its About page, card configuration and raw
  entity state were inspected read-only. A direct cover summary reproduced the
  missing numeric source: state `open`, position attribute `94`. This case is now
  covered by regression tests and a readable Value source dropdown, including a
  Position (%) suggestion for cover groups. After testing the candidate, the
  maintainer confirmed the tested changes work on this HA 2026.10 setup, including
  the numeric summaries/value-source picker and window icons. Door/garage icon
  variants are covered by automated tests.
* On 2026-11-13 the maintainer reported using **HA 2026.11** without observed
  problems, including the built-in images. Exact patch version and a fresh
  installation with cache disabled were not recorded. Previously installed
  image files or browser cache could hide #161; neither explanation is confirmed.
  This report applies to the existing installation, not the new packaging fix.

## Official compatibility references

* [Frontend component changes](https://contributors.home-assistant.io/blog/2026/10/28/frontend-component-updates-2026.11/):
  switch labels belong in the default slot after removal of the form-field wrapper.
  Both static and dynamic editor paths use that contract; editor DOM revision 10
  refreshes already-open editors. The
  [20260930.5 switch source](https://github.com/home-assistant/frontend/blob/20260930.5/src/components/ha-switch.ts)
  also uses the Web Awesome switch. The maintainer reported the tested changes
  working on HA 2026.10; a separate per-control live click matrix was not recorded.
* [HA name formatter](https://contributors.home-assistant.io/frontend/reference/hass-object/#formatentityname):
  default entity labels now delegate to `hass.formatEntityName()` when available.
  Explicit control text remains unchanged, including intentional empty strings;
  older HA versions and missing registry data fall back safely.
* [Dashboard packaging](https://contributors.home-assistant.io/marketplace/guides/dashboard/):
  the explicit filename and bundled `dist/` assets fit the existing plugin format.
  README installation guidance now distinguishes Marketplace from older HACS.
* [Marketplace migration and releases](https://contributors.home-assistant.io/marketplace/how-it-works/):
  the shared catalog and manifest remain applicable. Existing HACS resource paths
  are documented as compatible. These published contracts still need the live
  RoomCard checks below.
