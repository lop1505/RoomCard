## Testbranch über Marketplace installieren

Der Teststand liegt auf dem Branch
[`codex/test-automatic-room-sections-20261113`](https://github.com/lop1505/RoomCard/tree/codex/test-automatic-room-sections-20261113).
Er ist kein Release. Der normale Repository-Link allein installiert weiterhin die
veröffentlichte Version.

1. Falls RoomCard bereits im Marketplace installiert ist, den vorhandenen Eintrag
   verwenden. Andernfalls unter **Einstellungen → Marketplace → Add from link**
   `https://github.com/lop1505/RoomCard` als Dashboard-Projekt hinzufügen.
2. In **Einstellungen → Werkzeuge → Aktionen** die Aktion **Update installieren** (`update.install`)
   auswählen. Als Ziel die **RoomCard-Updateentität** aus dem Marketplace wählen.
3. Im optionalen Feld **Version** exakt
   `codex/test-automatic-room-sections-20261113` eintragen und die Aktion ausführen.
   Der Parameter bestimmt den zu installierenden GitHub-Stand; die im Code
   angezeigte Versionsnummer bleibt für diesen Kandidaten 1.5.1.
4. Nach Abschluss das Dashboard vollständig neu laden. Der Marketplace verwaltet
   den bestehenden Ressourceneintrag und versieht ihn mit der installierten
   Version. Keine zweite RoomCard-Ressource hinzufügen.

Die Versionseingabe unterstützt öffentliche Branches und vollständige
Commit-SHAs ([HACS-Dokumentation](https://www.hacs.dev/docs/use/entities/update/));
auch [HA 2026.11 übergibt den Parameter an den Repository-Installer](https://github.com/home-assistant/core/blob/2026.11.0/homeassistant/components/marketplace/update.py#L147).
Für reproduzierbare Nachtests kann die vollständige Commit-SHA aus dem GitHub-Link
anstelle des Branchnamens verwendet werden. Den gewählten Stand beim Test notieren.

## Alternative: lokales Testpaket installieren

1. Die bisherige RoomCard-Ressourcen-URL notieren oder kopieren, damit sie nach
   dem Test wiederhergestellt werden kann. Bestehende HACS-Dateien behalten.
2. Das Testpaket entpacken. `room-card.js` und alle 16 `.jpg`-Dateien gemeinsam
   nach `/config/www/roomcard-test/` kopieren. Die Bilder liegen direkt neben der
   JavaScript-Datei; ein alter `rooms/`-Ordner wird nicht benötigt.
3. Unter **Einstellungen → Dashboards → Ressourcen** die bestehende
   RoomCard-Modulressource vorübergehend auf
   `/local/roomcard-test/room-card.js?test=20261113` ändern. Bei YAML-Ressourcen
   entsprechend den bestehenden Eintrag ändern. Für diesen Test eine einzige
   RoomCard-Ressource laden, damit die Reihenfolge zweier Builds keine Rolle spielt.
4. Dashboard vollständig neu laden, möglichst mit deaktiviertem Browser-Cache.
   Falls bereits eine frühere Fassung dieses Testpakets geladen war, den
   `test`-Parameter ändern und erneut vollständig laden.

## Lokale Prüfung

`npm run check` besteht mit **160 Tests**, Syntaxprüfung, reproduzierbarem Bundle
und Versionsabgleich. Der Testbuild wurde im Browser mit simulierten HA-Daten
geprüft; das Raumbild wurde tatsächlich geladen, und es gab keine Konsolenfehler.

Die automatisierten Tests prüfen die Auswahlregeln, unveränderte gespeicherte
Konfiguration, Editor/Save-Ablauf, Drawer-Vorschau, stabile Karteninstanz, Fokus,
Klappzustand, entfernte Bereiche und sämtliche Bilddateien. Zusätzlich wurde die
Browser-Vorschau mit simulierten HA-Daten bedient. Das ersetzt den heutigen
Live-Test der nativen HA-Abschnittsauswahl und der Registry-Aktualisierungen nicht.

Die lokale Browser-Vorschau lässt sich mit einem HTTP-Server im Repository unter
`tests/fixtures/automatic-room-section.html` öffnen; sie schaltet keine echten
Geräte und speichert nichts in Home Assistant.
